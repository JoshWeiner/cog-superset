# Web-Only Dependencies Scan (Mobile/RN Port)

Static report enumerating occurrences of browser-only globals/APIs in the Superset frontend that would not be available when the same source is compiled for a React Native mobile target. **No source code is modified by this PR** — it adds only this report to guide subsequent porting work.

## Scope

- Roots scanned: `superset-frontend/src/**`, `superset-frontend/packages/superset-ui-core/src/**`
- File types: `*.ts`, `*.tsx`, `*.js`, `*.jsx`
- Excluded: `*.test.*`, `*.stories.*`, `*.spec.*`, `*.d.ts`, `**/spec/**`, `**/__tests__/**`, `**/__mocks__/**`, `**/fixtures/**`
- Tool: `ripgrep` (default RE2 engine) plus light Python post-filtering for known false positives.

## Notes & caveats

- Pattern matching is purely lexical. Some hits will be false positives (e.g. `fetch` used as a parameter name, `window` as a substring of a variable name, comments). The report intentionally errs on the side of over-reporting — humans should review and discard before refactoring.
- `navigator.platform` is excluded per the task spec; other `navigator.*` usages (clipboard, userAgent, etc.) are flagged.
- `location` matches are filtered to `window.location` / `document.location`; `useLocation` from `react-router` and the router's `location` prop are not flagged.
- `fetch` matches exclude lines that mention `SupersetClient` and identifiers like `prefetch`, `refetch`, etc.
- Tests, stories, mocks, fixtures and `*.d.ts` are excluded so the report reflects production code that would ship to the RN bundle.

## How to regenerate

This report was produced by an ad-hoc script that runs `ripgrep` for each API category, filters obvious false positives, and groups by the nearest `src/components/<X>/` or feature directory. The script is not committed; to regenerate, run `ripgrep` per the regexes in the *API categories* table above against the scoped roots.
